## TL;DR
> One hallucinated or misinterpreted command can wipe out months of work, no matter how autonomous your agent is. IndyDevDan demos his open-source "Claude Code Damage Control" skill, which layers deterministic PreToolUse command blocking, an AI-driven "prompt hook" that catches dangerous commands it's never explicitly seen, ask-for-confirmation patterns, and path-level protections (zero-access, read-only, no-delete) on top of Claude Code Hooks — installable in any repo with a single `/install` prompt, plus a global version that protects every codebase on the machine.

**Watch this if:** you run Claude Code with broad permissions (or in "Yolo mode") against a real production codebase or database.

## Key Takeaways
- Claude Code Hooks support four damage-control layers: local (project-level) deterministic hooks, an AI-driven "prompt hook," ask-permission patterns, and global (user-level, machine-wide) hooks.
- The prompt hook runs an AI check against every bash command and catches dangerous commands you never explicitly blocked (e.g. deleting all hook files) — it's a probabilistic last-ditch safety net, not a replacement for deterministic rules.
- As soon as a new dangerous command is discovered via the prompt hook, it should be hard-coded into the deterministic `patterns.yaml` blocklist so it's caught instantly next time.
- A lightweight `patterns.yaml` file wraps Claude Code's native hook system to define blocked commands, "ask" commands (agent must pause and get explicit confirmation), and path protection levels.
- Path protections come in three tiers: zero-access paths (agent can't read/write/do anything), read-only paths (agent can read but not modify), and no-delete paths (agent can modify but never delete).
- The whole system installs via a `/install` slash-command workflow (an agentic "cookbook" using the ask-user-question tool) that lets you choose global, project, or personal scope and Python (uv) or TypeScript (Bun) tooling.
- Claude Code Hooks run PreToolUse checks in parallel, so multiple deterministic and prompt-based hooks race — any one of them blocking is enough to stop a dangerous command.
- Recommendation: set up at least global hooks (protect every codebase on your machine) plus project-level hooks for anything production-facing, and treat this as an alternative to needing "trust" in your agent at all.
