## TL;DR
> IndyDevDan breaks context engineering with Claude Code into beginner, intermediate, advanced, and "agentic" levels, all reducible to one framework — R&D: Reduce and Delegate. He demonstrates deleting default MCP server configs to reclaim ~20k tokens, replacing a bloated CLAUDE.md with lean "context priming" slash commands, delegating work to sub-agents (system prompts that don't pollute the primary context) to save ~40k tokens, using Claude Code hooks to build "context bundles" that let a fresh agent replay a previous session's work, and spinning up fully independent background primary agents via a simple custom `/background` command.

**Watch this if:** you're hitting Claude Code context-window limits or bloated CLAUDE.md/MCP overhead and want concrete techniques to reduce and delegate context across single and multi-agent workflows.

## Key Takeaways
- Every context engineering technique reduces to R&D — Reduce (cut what enters your primary agent's context window) or Delegate (push work into sub-agents or other primary agents instead).
- Beginner mistake: a default, always-loaded `mcp.json` can silently consume 12%+ of the context window (24k+ tokens in the demo); delete it and load MCP servers by hand with `claude --mcp-config <file>` (optionally `--strict-mcp-config`) only when a task actually needs them.
- A bloated CLAUDE.md file is "incredible and terrible for the same reason" — it's always loaded into every agent's context window; Claude Code itself warns when it gets too large, and the fix is trimming it to only near-universal essentials (the demo cut a file consuming ~10% of context down to ~0.2%).
- "Context priming" (dedicated, reusable slash commands like `/prime` that read specific files for a specific task type) beats static memory files because it's dynamic and controllable — you can build multiple prime commands (bug-fixing, feature work, a specific subsystem) instead of one file that only ever grows.
- Sub-agents run as system prompts, not user prompts, so their context doesn't get added to the primary agent's window — delegating a doc-refresh task to ~10 sub-agents (loading AI docs, web-scraping each with Firecrawl) kept the primary agent under 9k tokens while the sub-agents burned ~30k+ tokens collectively, for a combined savings of roughly 40k tokens versus doing it all in one context.
- Context bundles use Claude Code hooks to append a running log (reads/searches/writes) of what an agent has done, tagged by session; a fresh agent can `/load-bundle <path>` to replay ~60-70% of a previous agent's understanding after a context window "explodes," without re-doing every read.
- Primary multi-agent delegation (via a simple custom `/background` command) spins up an entirely separate, fully independent Claude Code instance in the background with its own prompt, model, and report file — freeing the in-loop primary agent completely and reporting results asynchronously when done.
- The overarching philosophy: managing context isn't about hoarding tokens, it's about spending them properly — investing in fewer, more focused single-purpose agents (rather than one overloaded agent) is a safe long-term bet as model performance degrades with growing context.
