# Claude Code 2.0 Has Arrived (It's Insane)

## TL;DR
> A walkthrough of four recent Claude Code updates: `/loop` for short-lived recurring/one-off tasks inside a session, Scheduled Tasks for persistent daily/weekly automation (desktop/Cowork only), the open-source Google Workspace CLI for full Drive/Docs/Sheets/Slides access with proper formatting, and Skills 2.0 — built-in evaluation/testing for skills via an updated Skill Creator that scores outputs against custom criteria and lets you A/B test skill versions.

**Watch this if:** you want Claude Code to run on a schedule instead of only when you're actively prompting it, or you want a systematic way to actually improve a skill instead of guessing.

## Key Takeaways
- `/loop` schedules recurring prompts (or one-off reminders) inside your *current* session using cron under the hood (three tools: cron create, cron list, cron delete) — e.g. `/loop every 10 minutes, check my inbox`. Limitations: loops expire after 3 days (a safety measure), only live in the session that created them, and don't catch up if the session was closed when they should have fired — they just vanish.
- Scheduled Tasks are the persistent counterpart: set a prompt, model, and schedule (daily/weekly/hourly), and each firing starts a fresh instance that reads project files, runs relevant skills, and stops when done. Currently desktop-app/Claude Cowork only (not terminal or VS Code extension), requires the computer on and app open, but — unlike loops — missed runs do catch up when reopened.
- Google Workspace CLI (Google's own open-source, beta tool, not an official Claude Code feature) gives one tool full access to Drive, Gmail, Calendar, Docs, Sheets, and Slides with 100+ built-in recipes, fixing Claude Code's previous lack of a good Google Drive MCP server. It runs bash commands that talk directly to Google, producing properly formatted documents (headers, images, links) instead of raw Markdown needing manual API formatting calls.
- Skills 2.0: Anthropic updated the Skill Creator skill to include proper evals — you can now test a skill against specific, self-defined criteria and get scored results back instead of a vague pass/fail.
- Recommended eval workflow: build the skill with Skill Creator (clear name, trigger description, goal, required tools/connectors, reference files, step-by-step process, human-in-the-loop checkpoints); then run a *specific* eval request (e.g. "test whether my copy uses curiosity gaps and founder-led stories from my persuasion toolkit reference file") rather than a vague "run some tests" — focus on 1-3 criteria at a time rather than testing everything at once.
- Evals run multiple variations in parallel via sub-agents and produce a browsable HTML report with per-run pass/fail breakdowns and specific feedback (e.g. "copy lacks genuine curiosity gaps that sustain across multiple sentences"), which you feed back into Claude Code to revise the skill.md and re-run.
- You can also A/B test a skill's actual value: run the same task with and without the skill (or with a stripped-down reference-file set) to see whether it's genuinely improving output quality or just costing tokens.

## ✅ Action Items
- Use `/loop every X minutes/hours, <task>` for short-term monitoring (a few hours to a few days), not for anything you need to run indefinitely.
- Set up a Scheduled Task (via the desktop app or Cowork) for anything that needs to run every day/week reliably, since it catches up on missed runs.
- Try the Google Workspace CLI if you've hit Claude Code's lack of native Google Drive/Docs support.
- When evaluating a skill, ask for a test optimized around 1-3 specific, named criteria (tied to a reference file) instead of a generic "run some tests" request.
- A/B test a skill with and without it (or with fewer reference files) to confirm it's actually earning its token cost.
